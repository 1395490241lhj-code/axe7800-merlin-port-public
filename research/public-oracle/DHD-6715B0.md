# DHD_6715B0 — end-to-end trace

## Where it is defined
`release/src-rt/target.mak` only. 7 models set `DHD_6715B0=y`: GT-AX6000, XT12, GT-AXE16000,
GT-AX11000_PRO, RT-AX86U_PRO, RT-AX88U_PRO, GT-BE98_PRO. It is **not** an `RTCONFIG_*`
(0 occurrences of `RTCONFIG_DHD_6715B0` anywhere).

## What it controls — exactly one thing
`release/src-rt-5.04axhnd.675x/targets/buildFS:471-476`

    if [ -f ${HND_SRC}/bcmdrivers/broadcom/net/wl/impl${BCM_WLIMPL}/sys/src/dongle/bin/6715b0/rtecdc.bin ]; then
      mkdir -p ${TARGET_FS}/rom/etc/wlan/dhd/6715b0          # directory: ALWAYS created
      if [ "${DHD_6715B0}" == "y" ]; then
        cp .../dongle/bin/6715b0/rtecdc.bin ${TARGET_FS}/rom/etc/wlan/dhd/6715b0   # copy: GATED
      fi
    fi

- **source**: `bcmdrivers/broadcom/net/wl/impl87/sys/src/dongle/bin/6715b0/rtecdc.bin`
- **destination**: `rom/etc/wlan/dhd/6715b0/rtecdc.bin` in the target filesystem
- So the flag decides **whether the dongle firmware is placed in the image**, nothing else.

Upstream of buildFS, `675x/Makefile:685-691` stages the per-model firmware:
`dongle/sysdeps/$(BUILD_NAME)/6715b0/rtecdc.bin` → `dongle/bin/6715b0/`, falling back to
`dongle/sysdeps/default/6715b0/rtecdc.bin` when no model directory exists.

## Which radio
6715b0 is the **BCM6715 PCIe radio = wl1, the 5 GHz DHD-attached radio** (`devpath1=pci/1/1`,
bootloader `dhd1=11`). It is **not** the 6 GHz radio: wl2 is SoC-attached (`devpath2=sb/1/`)
and runs through `wl.ko`, with no DHD dongle firmware.

## Difference between RT-AXE7800 and other 6756 targets
No 6756 model in the RMerlin tree sets `DHD_6715B0`; the seven that do are 4912/BE-class.
The **SWRT public RT-AXE7800 stanza does set `DHD_6715B0=y`**, and the stock 388_25206 image
ships `rom/etc/wlan/dhd/6715b0/rtecdc.bin` (2,750,488 B) — so the real product is built with it.

## Does clean-replay-v2 reach the same layout? **No.**
Our minimal target does not set `DHD_6715B0`, so buildFS creates the directory but **omits the
firmware**. Additionally there is **no `dongle/sysdeps/RT-AXE7800/` directory**, so even with
the flag set the `default/6715b0` fallback would be used — and that file does **not** match stock:

| source | size | sha256 (first 32) |
|---|---|---|
| **stock 388_25206** | 2,750,488 | `d4c760d14b4d953df716f6787af5f9b9` |
| sysdeps/default (and staged bin/) | 2,668,568 | `9247311245286569480add146e381d3d` |
| sysdeps/GT-AX6000 | 2,668,568 | `ec8101c3a53fbd7121fc5fd05b81989a` |
| sysdeps/RT-AX86U_PRO | 2,766,872 | `99629d3be8534ca2b72e1ff812002794` |

**No public copy matches the stock RT-AXE7800 firmware.** This identifies a previously
unaccounted-for per-model asset: `dongle/sysdeps/RT-AXE7800/6715b0/rtecdc.bin`.

Runtime-affecting only — it does **not** change the current `shared/prebuild` build blocker,
and nothing was altered.
